# lhg-amz-compliance：合规 checklist 与评分方法论

> 目标：上架前把 Listing 查三遍——机器查一遍（脚本）、合规查一遍（本 skill）、人工查一遍（复核清单）。
> 核心纪律：**有 blocker 就不许上架；类目对不对，机器查不出来，必须人看。**

## 1. 何时使用

- Listing 写完准备上架 → 走全流程（三遍检查）
- Listing 被下架/警告 → 按第 4 节逐条排查原因
- 接手别人的 Listing → 先打分再决定改还是重写

## 2. 输入与输出

**输入：** 完整的 Listing 文档（含标题/五点/Search Terms/图片/类目/描述）。

**输出：** 六维评分（百分制）+ 定级 + 按优先级排序的改进清单 + 合规结论（通过/不通过）。

## 3. 分步方法论：六维评分卡

### 3.1 评分维度与权重

| 维度 | 权重 | 满分标准 |
|---|---|---|
| 标题 | 25% | ≤200 字符、含核心关键词、无重复、无红线 |
| 五点描述 | 25% | 5 条齐全、每条一卖点、≤500 字符、参数可验证 |
| 关键词 | 20% | Search Terms ≤250 字节、无重复、低重叠、无 ASIN |
| 图片 | 15% | ≥6 张、主图 ≥2000px、有场景/细节/尺寸图 |
| 类目 | 5% | 有类目声明、节点与产品匹配（人工判） |
| 产品描述 | 10% | ≥200 字、补充 bullet 之外的信息 |

### 3.2 打分规则

- 每个维度 0-100 分，按"满分标准"逐项扣分
- 脚本 warning 一条扣该维度 10 分，nit 一条扣 5 分（示例口径）
- **有 blocker 的维度直接 0 分**，且总评定为"不通过"
- 总分 = Σ(维度分 × 权重)；定级：90+ 优秀 / 75-89 良好 / 60-74 待改进 / 60 以下重写

### 3.3 改进清单排序

按以下顺序输出改进项，每条写清"怎么改"：

1. blocker 项（违禁词/标题违规/Search Terms 超限/ASIN）——必须改
2. 高权重维度的 warning（标题/五点）——优先改
3. 低权重维度的 warning（图片/描述）——随后改
4. nit 项——顺手改

### 3.4 图片规范 checklist

- [ ] ≥6 张：主图 + 场景 + 细节 + 尺寸 + 包装 + 对比
- [ ] 主图白底、≥2000×2000（支持缩放）
- [ ] 每张图标注尺寸规范（审计规则 AMZ-IMG-002）
- [ ] 图片中的文字与 Listing 文案一致（价格/参数不错位）

### 3.5 类目 checklist（必须人工复核）

- [ ] 文档有类目章节，写清完整节点路径
- [ ] 类目与产品实际品类匹配（机器判不了，人看）
- [ ] 类目节点不是"其他/杂项"类兜底节点
- [ ] 变体关系正确（父子体、属性一致）

### 3.6 上架前最终检查表

| 检查项 | 通过标准 |
|---|---|
| 标题 | ≤200 字符、含核心词、无红线 |
| 五点 | 5 条、每条一卖点、参数可验证 |
| Search Terms | ≤250 字节、无重复、低重叠、无 ASIN |
| 图片 | ≥6 张、主图 ≥2000px、图文一致 |
| 类目 | 节点路径明确、与产品匹配（人工确认） |
| 描述 | ≥200 字、无编造 |

六项全过才能点上架，缺一项都是给未来埋雷。

### 3.7 下架/警告排查流程

1. 看通知：亚马逊的警告邮件会写违规类型，先对号入座
2. 跑审计：用脚本扫一遍，看 blocker 落在哪条规则
3. 查变体：重点查拼音/谐音/拆字等变体绕过
4. 改+申诉：改掉违规点，申诉时写清"改了什么、以后怎么避免"
5. 归档：把这次违规记进检查表，下次上架前多查一项

**注意：** 同一违规反复出现，处罚会升级。第一次是警告，第二次可能直接封店。

### 3.8 多站点注意事项

| 站点 | 注意事项 |
|---|---|
| 美国站 | 标题≤200 字符，FDA/环保宣称最严 |
| 欧洲站 | 需符合当地语言要求，CE 相关表述谨慎 |
| 日本站 | 标题习惯不同，建议参考本地 Top 卖家格式 |

**核心：** 不要把美国站的 Listing 直接翻译上其他站点。
每个站点的标题规范、违禁词表、类目结构都有差异，上架前按本站点重查一遍。

### 3.9 合规日历

| 周期 | 动作 |
|---|---|
| 上架前 | 三遍检查（脚本/合规/人工） |
| 每月 | 抽查在售 Listing：政策有无更新、文案是否过期 |
| 大促前 | 促销信息与 Listing 一致性复查 |
| 被警告后 | 48 小时内整改+申诉，并更新检查表 |

**原则：** 合规不是上架前的一次性动作，是持续动作。
政策更新不会通知到你，等你发现时可能已经违规了。

## 4. 反模式（这些做法一定错）

1. **有 blocker 还上架**："先上架再改"——下架警告来得比你改得快。
2. **类目错放**：保温杯放到"运动户外"大类下——流量全是错的，转化率被拖死。
3. **违禁词变体绕过**："治愈"写成"治愈力"、拼音首字母——平台一样能识别，罪加一等。
4. **参数前后矛盾**：标题写 1000ml，五点写 800ml——差评与退货的源头。
5. **图片文字与文案打架**：图片写"买一送一"，文案没写——客诉预定。
6. **为高分改规则**：评分低就去调脚本阈值——作弊，不许。

## 5. 自检与反馈

**质检门（三遍检查流程）：**

- [ ] 第一遍（机器）：跑审计脚本，blocker 清零
- [ ] 第二遍（合规）：按本节 checklist 逐项打勾
- [ ] 第三遍（人工）：按下面复核清单执行

**人工复核清单（脚本抓不到的）：**

- 类目节点是否放对（只能人看）
- 违禁词变体：拼音/谐音/拆字（如"治愈力""z愈"）
- 标题、五点、图片、描述四处的参数是否一致
- 售后承诺与店铺实际政策是否一致
- 有无编造的参数、销量、认证

**标准冒烟用例：** 用 `fixtures/amazon-bad/listing.md` 跑审计脚本，应命中全部 16 条规则中的 14 条以上且 blocker ≥3；用 `fixtures/amazon-good/listing.md` 跑，应零 blocker 且 exit 0。
